No features match that search — try another keyword. 🔍

🏢Hierarchy containment

Association → Pharmacy → Application → Dataset → Rows, enforced at every layer — a dataset can never point outside its application.

🎯One-field scope model

A user is either locked to one Pharmacy or has Association-wide visibility. No separate scope-state to manage, no toggle to forget.

🛠️Admin console

Association Admins create and manage Pharmacies and Users inside their own association via dedicated UI screens.

🗄️26-table canonical schema

PostgreSQL + PostGIS with a single migration chain; tenant boundary enforced by the database itself, not just app code.

🌱Idempotent demo seeding

make seed builds demo tenants, branches and users reproducibly — safe to run any number of times.

🌐RTL-ready bilingual UI

Bootstrap 5 official RTL bundle plus English + Arabic synonym dictionaries in the mapper — built for Egyptian pharmacy chains.

👥Five-role RBAC

Association Admin, Pharmacy Manager, Analyst, Data Steward, Viewer — each with a distinct permission matrix.

🚫Deny-by-default

Every write action requires an explicit per-route role match. There is no “allow if unsure” branch anywhere in the auth code.

🍪Signed sessions + bcrypt

Starlette SessionMiddleware with itsdangerous signed cookies; passlib bcrypt hashing; no public self-registration.

🔎RLS-safe authentication

Pre-login user lookup runs through a SECURITY DEFINER function, so authentication never needs to weaken row-level security.

🔑Secret validator

Refuses to boot outside development with the shipped placeholder signing key — forgeable session cookies can’t ship by accident.

🪧Friendly denial pages

403s render a proper page instead of leaking JSON; redirects stay clean for expired sessions.

📤Any pharmacy file

Single CSV, multi-sheet Excel, or a whole ZIP of mixed files — one upload, one bulk mapping page, one confirm.

📜Immutable bronze layer

Every upload is stored byte-for-byte and never rewritten. A bad mapping can always be re-run from the original file with zero loss.

✅Partial-success commit

Valid rows commit even when siblings fail; every skipped row comes back with a stated reason — bad rows never poison good ones.

♻️Duplicate-upload blocking

SHA-256 content hash per dataset: re-committing an identical file is refused with a clear message instead of silently doubling revenue.

🧾Transaction-level dedup

transaction_ref with DISTINCT coalesce(transaction_ref, row_id) counting keeps transaction counts honest across re-runs.

🏷️Hard attribution gate

Every row must resolve to exactly one pharmacy; an unattributable file halts and asks — it never silently proceeds.

🔤Bilingual fuzzy headers

rapidfuzz matching over English + Arabic synonym dictionaries (sale_timestamp / تاريخ البيع, total_amount / الإجمالي …).

📊Content-based inference

A second layer statistically inspects cell values — dates, numerics, categoricals — so headers that lie get overruled.

🚦Confidence-scored review

Per-field scores color the review UI green / amber / red; suggestions under 70% are suppressed, not guessed.

🙋Human-in-the-loop

Nothing is auto-committed without review — and confirmed mappings are remembered per application for the next upload.

🐣Canonical normalization

Column chaos collapses to canonical snake_case fields; unmapped source columns survive in a JSON attribute bag.

🧭Entity disambiguation

When a file could be sales or inventory events, the classifier says which — and asks when unsure.

📃Filterable grid

Paginated, filterable tables per canonical entity with HTMX partial-page updates — no full reloads.

✏️Guarded inline editing

Only allow-listed columns are editable, values are type-cast server-side (bad input → clean 400, never a 500).

🧾Audit-before-edit

Every mutation is logged — who, when, old value, new value — in the same transaction, before the change is applied.

⏪Append-only revert

Reverting writes a NEW audit entry; history is never rewritten, so any value’s full story is reconstructable.

🔒Pharmacy-scoped writes

A pharmacy-locked user editing another branch’s row gets a 403 — enforced on top of RLS, not instead of it.

🛑Mass-assignment shield

Clients cannot name non-editable columns like association_id — the allow-list refuses before the write.

💰Sales dashboard

Revenue, transaction count and average basket — with revenue-over-time and top-products charts in EGP.

💊Inventory & waste

Units near expiry, waste cost, turnover ratio, waste-by-product chart, and a 30/60/90-day expiring-batch table.

🎚Scope-aware everything

Every tile and chart respects the viewer’s scope automatically — no manual filter needed for pharmacy-locked roles.

🇪🇬Localized defaults

EGP currency stamping and Africa/Cairo timezone handling baked into ingestion and reporting.

🧪Nine analytics engines

Inventory optimization, ABC/XYZ, margins, payer performance, adherence, controlled substances, procurement/supplier — service layer ready, UI routes next.

🎯Real data, real tiles

KPI tiles render live query results — totals, dates and currency all come from your data, not placeholder zeros.

🏰Fail-closed RLS

All 24 tenanted-table policies rebuild the tenant key with nullif(…,'')::uuid — an empty context hides every row, it never opens the vault.

👥Two-role database

The app runs as a least-privileged role; the migration owner role can never be used to bypass isolation policies at runtime.

💣Zip-bomb guard

Total decompression is capped before reading (default 200 MB) — a tiny archive can’t exhaust memory or disk.

🧷Path-traversal shield

Upload and zip-entry names are reduced to sanitized basenames — ../../etc/passwd can’t escape the bronze root.

🛡️CSRF same-origin guard

Cross-site form POSTs are rejected with a 403 before any handler runs — live-verified against the running container.

📏Upload size cap

Oversized files are detected by reading just one byte past the limit — no memory blowout, just a friendly rejection page.

What we do not yet guarantee

A showcase that hides its gaps is marketing, not engineering. From SECURITY_SPEC.md, verbatim in spirit:

⏳ No login rate limiting yet

Brute-force protection is on the backlog — the same-origin guard does not throttle repeated attempts.

🔒 No encryption at rest

Disk-level encryption is deferred to deployment infrastructure, not handled in-app.

💾 No backups / DR story

Raw-file bronze storage is local-disk only; object storage migration is planned past ~50–100 GB.

🔓 Proxy-awareness caveat

CSRF compares against the Host header; X-Forwarded-Host support is needed behind reverse proxies.

🧱 No high availability

Single-node design by intent for pilot scale; HA is a post-pilot concern.

📉 Analytics UI pending

Nine analytics engines are implemented in the service layer; dedicated routes/templates are the next phase.
